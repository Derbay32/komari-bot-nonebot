# 按钮权限一次性实验探针（Throwaway Prototype）

> **本探针是一次性实验代码，属于 throwaway 分支，不进入 dev 主线，不是任何生产实现。**
> 实验结束后整支分支按结论归档或丢弃，禁止把本文件改进成正式功能。

## 目的

在真实 QQ 客户端回答一个问题：群机器人 Markdown 消息的按钮在三种
`action.permission` 配置下分别能否被点击：

- 指定本人名单（`type=0` + 触发者 OpenID）
- 指定空名单（`type=0` + 空列表）
- 所有人（`type=2`）

点击按钮只把对应命令填入输入框，用户手动发送后服务端回执，用以区分
“按钮可点击”与“命令确实到达”。

## 启动

1. 进入此原型 worktree，激活项目既有的 Python 3.13 虚拟环境。
2. 准备一份私有配置文件（格式见下，放在本仓库外或已忽略路径）。
3. 运行一条命令：

```bash
PYTHONPATH=. PERMISSION_PROBE_CONFIG=/absolute/private/config.json nb run -f komari_bot/plugins/character_binding/prototype_permission_probe.py
```

预期结果：日志出现 `探针已启动`，仅监听配置中的实验群。

## 配置格式

```json
{
  "qq_bots": [
    { "id": "<app-id>", "token": "<app-token>", "secret": "<app-secret>" }
  ],
  "qq_is_sandbox": false,
  "probe_group_openid": "<group-openid>"
}
```

- 配置只从上述显式文件读取，不读取 `.env`。
- `probe_group_openid` 为空或缺失时启动直接失败。
- 禁止把真实凭据或身份提交进仓库。

## 实验步骤

1. 在实验群中发送 `/permtest`。
   预期结果：收到一条 Markdown 消息，包含 A / B / C 三个按钮。
2. 依次点击三个按钮，记录每个按钮是否可点击。
   预期结果：可点击的按钮把对应 `/permtest X` 命令填入输入框。
3. 手动发送填入的命令。
   预期结果：收到对应字母的纯文本回执，回执只证明命令到达服务端。
4. 同一账号切换到另一客户端，在同一张已有卡片上重复步骤 2–3，不重新发送 `/permtest`。
   预期结果：获得原版 QQ 9.33.55.609 / iOS 26.6.2 与 QQ 7.0.0-52194 / macOS 26.6.2 的同卡对照。

可选：让其他群成员点击原触发者的同一张卡片，记录非本人表现。不要重新生成卡片，否则 A 会授权给新的触发者，不能作为非本人对照。

## 范围

- 探针只注册 QQ 适配器，只处理实验群内的 `/permtest` 命令。
- 探针不查询或修改角色绑定，不访问数据库或缓存。
- 探针不发送任何主动消息，所有输出都由群内命令触发。
- 胜出方案不会自动进入生产代码，需另开工单正式实现。

## 停止

1. 在运行终端按 `Ctrl+C` 停止进程。
   预期结果：进程退出，无任何持久化状态需要清理。
2. 保留或按需清理原型专用私有配置，不修改既有共享凭据。
   预期结果：实验不会破坏原服务配置；正式服务由主代理协调恢复，不自动启动。
