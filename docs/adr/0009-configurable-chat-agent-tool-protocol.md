# 将聊天回复建模为可配置的工具协议 Agent

聊天回复采用多轮回复 Agent，并将最终回复提交作为成功生成回复的唯一出口；裸文本输出永远不构成成功回复。回复 Agent 的轮次预算、单轮工具调用预算和总工具调用预算由 `komari_chat` 动态配置统一拥有，默认分别为 10、4、20，覆盖普通、debug 与简单回复入口，并在任务开始时冻结；模型提出的所有工具调用无论是否有效或执行成功都计入总预算。

工具调用约束模式分为 `required` 与 `prompt_guided`。前者要求模型服务强制产生工具调用，不兼容的模型配置明确失败；后者省略服务端强制参数，依靠数据库 Prompt 与有限纠错引导模型，但仍拒绝裸文本成功。裸文本轮次的输出和续接信息被丢弃，只保留诊断并消耗回复 Agent 轮次预算。共享 LLM provider 不再按思考模式暗中删除调用方的工具选择要求，各业务调用方必须显式声明兼容策略。回复 Agent 不做整任务重试，只有单次模型请求的瞬时故障可以在原逻辑轮次内重试，避免绕过轮次预算。

## Consequences

- DeepSeek V4 等不接受强制工具选择的思考模式必须由运维显式使用 `prompt_guided`，或关闭思考模式；系统不自动切换。
- 旧 `output_instruction` 不再作为第二套输出协议真源，由 Alembic 删除；角色风格、工具行为引导和最终结果结构分别归 `system_prompt`、`tool_call_instruction` 与最终回复工具 Schema。
