# 每次分发共享一次 Jev 判定，旧场景运行代码退役

## 决策来源

本决策取代本 ADR 原有的场景归类方案。
替换范围依据 TSK-180 第 1、5、7、10 节。
退役范围依据 TSK-159 最终决议 `esex34pdxot9b9obsag8clsr`。

## 当前决策

同次入站分发只执行一次 `evaluate`。
总结与聊天共享同一份冻结结果。
两个入口禁止重复调用模型或重新抽签。
总结命中后只允许领取总结交接资格。
总结未命中后，聊天按同一结果领取聊天交接资格。
持久化交接检查阻止平台重投重复执行业务。

旧聊天判定与旧总结场景归类全部退役。
旧场景管理、同步与向量生成服务全部退役。
旧场景专用管理路由与导入脚本全部删除。
禁止保留旧签名适配、场景分数兼容字段或故障回退入口。

## 保留边界

- 跨插件引用继续只走顶层暴露面，遵守 ADR-0006。
- 回复履约所有权保持不变，遵守 ADR-0008。
- 每个外部效果接受逐效果准入裁决，遵守 ADR-0012。
- 公共向量生成与重排能力继续服务记忆召回。
- 总结执行与调试总结保持有效。
- 既有回复履约恢复保持有效。
- 旧 4 张表及 38 个配置字段已由 `0025` 迁移删除。
- `0025` 在全新库与 0024 存量库上都验收为零漂移。
- `0025` 的 downgrade 拒绝回退，不重建表，不回填数据。

## 失败与停用

总结候选无法取得有效 Noul 时，停止总结与聊天两条路径。
技术失败通知直接使用既有共享通知接口。
普通判定失败不逐条发送群错误提示。

停用会撤销尚未交接结果的生效资格。
重新启用只处理新消息。
停用不追溯取消已经交接的业务。
后续业务效果仍接受当时的准入裁决。
不依赖模型的真实平台召唤继续使用持久去重与交接检查。

## 退役后果

旧场景管理 API 与后台任务不再注册。
`scene:read` 与 `scene:write` 不再授予场景管理能力。
既有凭据中的权限字符串仍满足通用语法。
不新增旧数据归档、导出、备份副本或恢复入口。
旧存储删除由独立的 `0025` 迁移承载。

## 历史理由（已废止）

旧方案把场景归类集中到判定插件内部。
旧方案禁止群总结自行持有场景运行状态、场景键与阈值。
旧方案通过专用异步操作向群总结返回归类结果。
这些实现决定随场景运行代码一起退役。

旧方案拒绝公开通用 `classify(purpose=...)` 接口。
当时的理由是调用方会承担其他用途的接口成本。

旧方案拒绝由群总结自行组装重排服务。
当时的理由是场景身份与失败语义会泄漏到判定插件之外。

旧方案拒绝重写稳定的聊天组合入口。
当时的理由是单一接口修复不足以支持扩大改造范围。

旧方案拒绝在旧宽重排服务外再加一层总结包装。
当时的理由是包装层仍会保留旧宽结果契约。
