## 背景与取舍

现有总开关混用了业务选择与依赖停用两种含义。
关闭共享记忆会阻止聊天回复。
关闭用户数据会导致好感度读取失败。
这些开关没有提供无记忆或无好感度的聊天模式。

网页能力同时受到总开关与两个业务开关限制。
搜索与抓取已有独立的启停选择。
删除重复总开关后，需要保留原有实际状态。

保留独立业务功能的停用能力。
删除只能使依赖方无法正常工作的停用能力。
接受无法再通过独立总开关暂停这些必需依赖。
使用明确的业务开关控制对应业务入口。

必需依赖不表示每条消息都需要远程请求。
必需依赖不表示依赖故障必须中止进程启动。

## System One 与必需依赖的故障边界

System One 不再提供人为停用状态。
删除当前健康状态中的 `disabled` 分支。
保留就绪与失败的真实状态区分。
保留现有安全失败原因码。

配置缺失或判定依赖不可用时，继续允许进程启动。
需要 System One 的操作在依赖不可用时明确失败。
管理入口在自身配置有效时保持可用。
不依赖 System One 的功能继续运行。

普通 @ 或引用角色消息继续使用免模型判定路径。
总结候选继续请求 System One 判定。
总结候选判定失败时，继续停止总结与聊天两条路径。
保留群准入、封禁与重复交接检查。

保留判定失败的既有通知规则。
保留判定失败的既有消息保存规则。
禁止将技术故障伪装为正常沉默。
禁止增加备用模型、固定规则或旧判定回退。

共享记忆不可用时，保留现有聊天失败边界。
用户数据不可用时，保留现有好感度读取失败边界。
禁止新增无记忆聊天模式。
禁止新增无好感度聊天模式。
