# 管理插件自身配置改为 dotenv 启动配置

状态：accepted。

管理面板是本项目的必要配置入口。
管理 API 的连接配置不能要求操作者先编辑数据库。
本决策依据本次需求“把 management 的配置从 pgsql 移到 dotenv 里”。

## 决策

管理插件自身的全部配置只读取 NoneBot dotenv／进程环境变量。
所有变量使用 `KOMARI_MANAGEMENT_` 前缀。
凭据和前端 Origin 使用 JSON 数组。
启动时继续执行凭据强度、唯一性、权限格式和时区校验。
默认配置保持禁用。
无有效凭据时不注册管理 API。

全部自身配置在重启后生效。
已加载凭据的 `revoked_at` 仍在每次鉴权时检查。
管理插件自身不再属于动态配置 API 的资源。
其他插件继续使用 PostgreSQL 强类型动态配置表。
公告业务存储继续使用 PostgreSQL。
本决策不表示整个管理服务可以脱离数据库运行。

本决策替代 ADR-0004 中管理插件自身配置的数据库存储规则。
本决策终止 ADR-0002 中管理凭据启动检查的数据库读取路径。
管理路由、Bearer 鉴权和权限语义保持不变。

## 迁移后果

迁移 `0034` 通过手写 DDL 删除 `komari_management_config`。
迁移拒绝降级。
升级前必须在私有部署配置中准备全部启动值。
代码不自动导出凭据。
代码不回退读取数据库配置。
生产迁移与重启仍需要单独授权。

## 排除的方案

不保留 dotenv 与 PostgreSQL 双重配置来源。
双重来源会让管理凭据的实际生效值产生歧义。
不只迁移 Token 与 Origin。
部分迁移会让管理插件自身继续依赖动态配置初始化。
