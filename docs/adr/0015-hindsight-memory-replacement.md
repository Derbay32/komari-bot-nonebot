# 使用 Hindsight 官方 SDK 替换自维护记忆系统

项目不再自行维护长期记忆的提取、整理和召回。
项目通过官方 Python SDK 接入外部 Hindsight 服务。
记忆替换不改变非记忆聊天逻辑。

本 ADR 记录已确认的设计决策。
本 ADR 尚未落实到生产代码。
生产迁移和部署由运维独立执行。

## 决策依据

本次记忆迁移访谈确认了以下范围：

- Q8 确认允许修改记忆接入点。
- Q10 确认只使用一个共享记忆库。
- Q14 确认移除自维护记忆系统。
- Q15 确认只迁移数据库内正式记忆。
- Q16 确认退役旧记忆专用接口。
- Q17 确认项目不负责管理 Hindsight。
- Q21 确认接收后不等待后台处理。
- Q22 确认不新增普通候选持久补写队列。
- Q23 确认 Hindsight 恢复后自动恢复聊天。
- Q24 确认一并改造模型按需召回工具。

共享记忆权限遵循 [ADR-0014](0014-shared-memory-admission-boundary.md)。
非记忆群准入继续遵循 [ADR-0012](0012-unified-group-admission.md)。

## 调用侧边界

- 使用官方 `hindsight-client`。
- 使用官方异步 SDK 方法适配现有事件循环。
- 复用项目既有配置管理方式。
- 配置服务地址、凭据和目标库标识。
- 将凭据标记为秘密配置。
- 使用运维预先配置的共享记忆库。
- 禁止隐式创建缺失的目标库。
- 禁止启动时覆盖 Hindsight 配置。
- 禁止在项目中部署 Hindsight 服务端。
- 禁止新增自有记忆提取或整理算法。
- 禁止保留旧实现、兼容接口或故障回退路径。

运维负责服务、模型、记忆库和记忆提示词配置。
项目提供调用侧所需的配置说明。
项目不接管 Hindsight 的后台任务管理。

官方接口依据：

- [Python SDK](https://hindsight.vectorize.io/sdks/python)。
- [写入接口](https://hindsight.vectorize.io/developer/api/retain)。
- [召回接口](https://hindsight.vectorize.io/developer/api/recall)。

## 写入与后台处理

- 保留现有记忆候选筛选。
- 将记忆候选交给 Hindsight 提取记忆。
- 在提交前执行适用的群准入检查。
- 采用 Hindsight 异步后台处理方式。
- 等待 Hindsight 确认接收提交。
- 在接收确认后继续当前回复流程。
- 禁止等待后台提取或整合完成后才回复。
- 禁止因已接收任务的后台处理而中断当前回复。
- 使用近期上下文理解尚未进入长期召回的当前交流。

接收确认不是处理完成证明。
项目不轮询每个在线任务来阻塞聊天。
后台单条内容失败不等于整个记忆服务不可用。

普通候选提交失败或无法确认接收时，停止本次聊天回复。
调用侧记录安全诊断。
普通候选不新增本地持久补写队列。
未确认接收的普通候选不承诺故障后补齐。

角色回复以平台确认送达为记忆写入依据。
已送达回复的写入继续遵循既有履约保障。
这项保障不扩展为全部群消息的持久补写队列。

## 召回与回复接入

- 在每次回复前执行官方记忆召回。
- 将现有模型记忆工具改为 Hindsight 按需召回。
- 移除旧记忆工具接口及专用输出结构。
- 禁止通过旧数据结构适配层维持兼容。
- 保留非记忆工具及其调用预算。
- 保留回复正文生成逻辑。
- 保留最终回复提交机制。
- 保留好感度处理逻辑。
- 保留平台发送和送达确认逻辑。
- 将召回内容通过既有不可信上下文边界交给回复模型。
- 禁止将召回内容视为系统指令或授权依据。

调用侧固定目标库和授权范围。
模型不能通过工具参数选择其他记忆库。
项目不使用 Hindsight 替换最终回复模型。
自动后台认知能力不因本次接入而关闭。
是否启用具体后台能力由运维配置。

## 可用性与恢复

- 将 Hindsight 可用设为聊天回复的必要条件。
- 在初始化无法访问目标库时禁用聊天回复。
- 在本次召回失败时停止本次聊天回复。
- 禁止把召回异常转换为空记忆继续回复。
- 允许正常返回空记忆的请求继续回复。
- 保持不依赖记忆的功能运行。
- 在调用能力恢复后自动恢复聊天回复。
- 禁止补发故障期间跳过的回复。
- 禁止通过恢复检查修改 Hindsight 配置。

单独的数据库健康响应不足以证明召回可用。
恢复检查必须验证目标库访问和实际召回能力。
具体超时和检查间隔采用显式调用侧配置。
后台运行管理不属于调用侧恢复职责。

## 一次性迁移

- 只迁移数据库内已经保存的正式记忆。
- 排除缓存和未整理的候选内容。
- 排除旧运行中的处理任务。
- 使用官方 SDK 写入目标库。
- 保留现有内容及可用来源字段。
- 使用稳定来源标识识别迁移记录。
- 核对来源记录覆盖情况。
- 核对迁入内容与源内容的一致性。
- 确认后台导入任务已经完成。
- 将失败或无法确认的记录列入迁移结果。
- 禁止只凭接收确认报告迁移完成。
- 禁止迁移脚本自动删除源数据。

不恢复已经删除或压缩丢失的内容。
不导入旧向量。
不增加召回效果基准或长期效果评测。
保留代码变更所需的正常测试与 CI 验收。

运维负责一次性停机、迁移和上线。
项目不实施新旧双写或在线追赶迁移。
迁移失败时保持聊天禁用并向前修复。
禁止回退到旧记忆实现。

## 取舍

接受服务故障导致聊天暂时不可用。
接受未确认接收的普通候选可能丢失。
接受新写入内容不是立即可召回。
用这些边界避免重建自有记忆运行系统。
保留已送达回复的既有责任边界。
