# 使用版本化初始数据播种提示词与场景

短标量动态配置继续由 Pydantic Schema 提供默认值并初始化 PostgreSQL；长文本 Prompt 与判定场景改由版本化初始数据文件通过统一初始化命令写入数据库。容器 prestart 在 Alembic 升级后执行初始化，本地部署使用同一命令；运行时只读取 PostgreSQL，绝不把初始数据文件或 Python 长文本默认值当作 fallback。

初始化器只插入缺失记录、补齐空字段，并以 `scene_key` 等稳定业务键幂等执行，绝不覆盖已有非空 Prompt 或管理员场景。弃用字段不由初始化器推测删除，而必须同时从 Schema、管理元数据和运行时代码移除，并由显式 Alembic revision 删除数据库列。本方案按协调式破坏性升级交付，不提供新旧 Schema 双读、双写或运行时兼容期。

## Consequences

- 聊天、记忆总结、群总结的 Prompt 缺失会阻止冷启动。
- 必需场景缺失会阻止冷启动。
- 成功加载后遇到数据库暂时故障，进程继续使用最后一次有效快照。
- 初始数据只用于初始化，不用于持续同步数据库。
- 恢复出厂内容必须使用独立、显式的运维操作。

## 判定 Prompt 的隔离初始化

依据：TSK-180《Jev 主判定替换实装规格》第 10 节。

将判定 Prompt 保存到独立的版本化初始数据文件。
继续使用 `seed_bootstrap` 命令执行初始化。
使用 `--decision-seed-file` 显式指定判定初始数据文件。
默认文件为 `komari_bot/db/initial_data/decision_prompt.yaml`。

保留原有 3 组 Prompt 的冷启动检查。
保留必需场景的冷启动检查，直至 TSK-183 删除场景实现。
独立解析判定文件，避免文件错误影响必需资源的校验。
继续拒绝初始数据文件中的重复键。

在必需资源提交并通过校验后，归还必需步骤的连接。
从共享引擎另行借用连接，以独立事务写入判定 Prompt。
将可选步骤的借用、事务及归还纳入同一失败隔离范围。
只插入缺失记录或补齐空字段。
保留数据库中已有的非空文案。
判定初始数据的读取、校验或写入失败不阻止角色服务启动。
针对判定初始化失败，只记录固定诊断，不输出文案或原始异常。

运行时仍只读取 PostgreSQL 中的 Prompt。
如果数据库中没有有效判定 Prompt，判定状态为 `failed`。
如果数据库中已有有效文案，初始数据文件缺失不使判定失效。
不增加文件回退、Python 长文本默认值或模型探测。

## 判定配置的启动失败隔离

依据：TSK-180《Jev 主判定替换实装规格》第 7 节。

将判定配置的静态 `startup_required` 声明设为 `False`。
保持其他配置资源的默认声明为 `True`。
将静态声明排除在数据库列和管理可写字段之外。

可选配置预热失败时，启动流程继续初始化后续资源。
失败的可选配置不发布默认快照。
后续初始化重试仍读取真实配置来源。
必需配置预热失败仍阻止启动。
取消信号仍向调用方传播。
