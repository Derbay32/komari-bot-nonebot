# 使用版本化初始数据播种提示词与场景

短标量动态配置继续由 Pydantic Schema 提供默认值并初始化 PostgreSQL；长文本 Prompt 与判定场景改由版本化初始数据文件通过统一初始化命令写入数据库。容器 prestart 在 Alembic 升级后执行初始化，本地部署使用同一命令；运行时只读取 PostgreSQL，绝不把初始数据文件或 Python 长文本默认值当作 fallback。

初始化器只插入缺失记录、补齐空字段，并以 `scene_key` 等稳定业务键幂等执行，绝不覆盖已有非空 Prompt 或管理员场景。弃用字段不由初始化器推测删除，而必须同时从 Schema、管理元数据和运行时代码移除，并由显式 Alembic revision 删除数据库列。本方案按协调式破坏性升级交付，不提供新旧 Schema 双读、双写或运行时兼容期。

## Consequences

- Prompt 或必需场景在冷启动时缺失会阻止应用启动；进程成功加载后遇到数据库暂时故障，可以继续使用最后一次确认有效的内存快照。
- 初始数据是 bootstrap seed，不是持续同步的期望状态；恢复出厂内容必须通过独立、显式的运维操作完成。
