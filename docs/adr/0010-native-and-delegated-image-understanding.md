# 将图片理解划分为原生与委托模式

聊天图片理解显式分为 `native` 与 `delegated`，新安装默认使用后者。原生图片理解由聊天模型直接接收经过安全下载与校验的图片；委托图片理解只向回复 Agent 暴露稳定图片索引，由 Agent 按需调用独立视觉模型取得文字描述。`komari_chat` 拥有模式和图片输入预算，`llm_provider` 只拥有视觉模型连接与推理槽位；启用委托模式不再把整个回复 Agent 切换到视觉模型。旧图片配置由 Alembic 从 `komari_memory` 一次性迁入后删除，不保留运行时兼容读取。

委托模式按索引懒下载并在单次回复 Agent 内缓存成功与失败结果，原始 URL 不发送给模型，任务级下载预算不能通过重复调用重置。Agent 自行判断是否需要读取图片；在读取前不得声称看到了图片内容。两种模式禁止自动降级，多图保持稳定索引并允许部分失败继续，全部图片不可用或原生多模态请求失败才终止回复。

## Consequences

- 图片理解失败复用统一群任务通知边界：技术诊断仅向 SUPERUSER 汇总通知，整体回复失败时保留既有群内固定道歉。
- 每个回复 Agent 最多提交一次图片理解失败汇总，再叠加共享冷却；通知不得包含 URL、base64、消息正文或视觉描述。
